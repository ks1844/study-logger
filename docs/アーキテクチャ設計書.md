# アーキテクチャ設計書（Study Logger）

## アーキテクチャ概要
Study Logger は、クリーンアーキテクチャをベースにした 4 層構造で構築する。

- web-app（UI層）  
  Razor Pages による SSR（サーバーサイドレンダリング）。  
  画面表示・入力受付・アプリケーション層の呼び出しを担当。

- application（アプリケーション層）  
  ユースケース（操作の流れ）を実装する層。  
  domain と infrastructure の橋渡しを行う。

- domain（ドメイン層）  
  エンティティ・値オブジェクト・ビジネスルールを保持する層。  
  アプリの中心となるルールを表現する。

- infrastructure（インフラ層）  
  DB や外部 API（AI など）との接続を担当。  
  application 層のインターフェースを実装する。

## 各層の責務

### web-app（UI層）
- Razor Pages による画面表示  
- 入力フォームの受け取り  
- PageModel で application 層のサービスを呼び出す  
- UI ロジックのみを持つ

### application（アプリケーション層）
- ユースケース（操作の流れ）を実装  
- domain と infrastructure の橋渡し  
- Repository インターフェースを定義  
- DTO を使ってデータを受け渡す

### domain（ドメイン層）
- エンティティ（User, Category, StudyRecord など）  
- 値オブジェクト（Email, StudyHour など）  
- ドメインルール（不変条件など）

### infrastructure（インフラ層）
- DB アクセス（EF Core）  
- Repository の実装  
- AI クライアント  
- 設定ファイルの読み込み

---

## 依存関係
web-app → application → domain
- domain はどこにも依存しない（中心）
- application は domain に依存する
- infrastructure は application のインターフェースを実装する
- web-app は application を呼び出すだけ

- Clean Architecture

---

## データフロー（例：学習記録の作成）

1. web-app の Create ページで入力  
2. PageModel が application の CreateStudyRecordService を呼ぶ  
3. application が domain のエンティティを生成  
4. application が infrastructure の Repository を呼ぶ  
5. infrastructure が DB に保存  
6. web-app に結果を返す
