# 学習記録アプリ 要件定義書

## 概要
IT企業未経験者向けの学習記録アプリ。

### 目的
- 学習者が自身の学習状況を記録・可視化し、今後の学習に役立てること。
- 学習内容をもとに職務経歴書などに活用できる自己PRを生成し、就職活動に役立てること。

- ターゲット：学習者、管理者（営業担当など）
- プラットフォーム：Web

---

## 実現する価値

### 学習者
- 学習記録の可視化  
- 日報管理による振り返り  
- 学習内容から自己PRを自動生成  

### 管理者
- 所属会社の学習者の学習状況を把握  
- 自己PRの確認  

---

## MVP機能

### ユーザー認証
- メールアドレス + パスワードで登録・ログイン
- ロール管理  
  - 学習者：自分のデータのみ閲覧・編集  
  - 管理者：所属会社の学習者データを閲覧可能  
- 1ユーザーにつき1社所属

---

### 学習カテゴリ管理
- CRUD（作成、取得、更新、論理削除）
- 学習者は自分専用のカテゴリを作成可能
- カテゴリ名は文字列
- DBに色は保存せず、ダッシュボード表示時のみ自動で色分け

---

### 学習記録
- CRUD（作成、取得、更新、論理削除）
- 記録内容  
  - 日付  
  - 学習カテゴリ  
  - 学習時間（FLOAT型、例: 2.5h）  
  - メモ / 備考  

---

### 日報
- CRUD（作成、取得、更新、論理削除）
- 内容  
  - 今日の目標  
  - 達成したこと  
  - 苦戦したこと  
  - 苦戦をどのように乗り越えたか  

---

### ダッシュボード
- 学習記録の可視化（総学習時間、平均学習時間）
- カテゴリ別色分け（表示時のみ自動着色）
- 自己PR生成機能を組み込み

---

### 自己PR生成
- CRUD（作成、取得、更新、論理削除）
- 学習記録をもとに100文字程度の自己PRを生成
- 学習者は自分のPRのみ編集可能

---

## データ構造

### USER（ユーザー）
- id  
- name  
- email  
- password  
- role（student / admin）  
- company_id  
- is_deleted  

### COMPANY（会社）
- id  
- name  
- is_deleted  

### CATEGORY（学習カテゴリ）
- id  
- user_id  
- name  
- is_deleted  

### STUDY_RECORD（学習記録）
- id  
- user_id  
- category_id  
- study_hour  
- memo  
- is_deleted  

### DAILY_REPORT（日報）
- id  
- user_id  
- date  
- goal  
- achieved  
- struggle  
- overcame  
- is_deleted  

### PR_SUMMARY（自己PR）
- id  
- user_id  
- content  
- is_deleted  

---

## 技術要件
- フロントエンド：HTML, CSS, TypeScript
- テンプレートエンジン：Thymeleaf
- バックエンド：C# / ASP.NET Core
- DB：MySQL（本番はAWS RDS想定）
- 認証：メール + パスワード
- AI：自己PR生成（100文字程度）

---

## 制約条件
- レコードの削除は論理削除とし、物理削除は禁止
- カテゴリの色はDBに保存せず、表示時に自動着色
- Googleカレンダー連携は不要
- ソーシャルログイン（Google等）は不要
- 推移グラフは不要

---

## 開発手法
- 仕様駆動開発  
  - 要件定義書、ER図、API仕様書を作成  
  - 仕様書をもとにAIでコード生成  
  - 生成コードを手動で補正し動作確認  
  - MVP機能を優先して実装
